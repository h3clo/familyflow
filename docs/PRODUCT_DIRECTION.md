# Family Flow 제품 방향 (2026-11-09)

## 목표 경험

**A형 — 먼저 챙겨주는 가족 생활 비서**를 기본으로 한다.  
가능하면 **C형**처럼 능동 제안과 자유로운 AI 대화를 결합하되, AI는 보조 계층이다.

장보기 체크리스트는 **기반 기능으로 유지**하되, 최종 UX의 중심이 아니다. 중심은 홈의 **오늘 할 일 / 제안 카드**다.

## 계층

1. **규칙 엔진 (필수):** 재고·식단·구매/생활 패턴으로 필요한 일을 먼저 제안. AI 없이도 동작.
2. **AI 대화 엔진 (선택):** 자연어 이해, 추천 설명, 식단·장보기 변경안 초안.
3. **AI Provider 어댑터:** NVIDIA NIM / Ollama 등 교체 가능. 키·엔드포인트는 서버 또는 로컬 전용.
4. **승인 파이프라인:** AI·규칙은 구조화 `ActionProposal`만 만들고 → 검증 → 사용자 승인 → 저장.
5. **민감 데이터:** 건강 등 개인 민감 정보는 외부 AI에 기본 전송 금지.
6. **오프라인:** Mac/AI 서버 불가 시에도 규칙 엔진·공동 데이터·장보기·재고 정상 동작. 대화 UI는 “연결 없음” 상태로 폴백.

## NVIDIA 무료 API

개발·테스트 전용으로만 가정. 가족 실사용 전 라이선스·비용·데이터 정책을 별도 검토한다.

## 구현 단계 요약

상세는 Cursor Canvas 「Family Flow A형 방향 재검토」 참고.

- S0 방향 문서화 (본 파일)
- S1 제안 엔진 + 홈 화면 (규칙만) ✅
- S2 ActionProposal 승인 UX ✅ (`docs/ACTION_PROPOSAL.md`, 미리보기→승인→원자 저장)
- S3 AI provider 인터페이스 + Ollama 스모크 ✅ (`docs/AI_PROVIDER.md`, 더보기 연결 테스트, `/api/ollama` 프록시)
- S4 대화 → proposal 변환 ✅ (홈 「말해 보세요」, 스키마 검증 후 승인)
- S5 이후: 패턴 학습 강화, Supabase, 배포 (승인 후)
