# Family Flow 제품 방향

운영 상태·대기열은 [PROJECT_GUIDE.md](PROJECT_GUIDE.md), 확정 결정은 [DECISIONS.md](DECISIONS.md), 구조는 [ARCHITECTURE.md](ARCHITECTURE.md).  
이 파일은 **제품 방향 설명**만 유지하고 진행 체크리스트의 최신본은 가이드를 따른다.

갱신: 2026-11-10 (NIM·배포·장기 확장 구분).

## 목표 경험

**A형 — 먼저 챙겨주는 가족 생활 비서**를 기본으로 한다.  
능동 제안과 짧은 AI 대화를 결합할 수 있으나, **AI는 보조 계층**이다.

장보기 체크리스트는 **기반 기능으로 유지**하되, 최종 UX의 중심이 아니다. 중심은 홈의 **오늘 할 일 / 제안 카드**다.

## 계정·가족 모델 (확정)

**기본은 “우리 집 계정 하나”다.** 가족 구성원마다 Supabase/앱 계정을 만들라고 요구하지 않는다.

- 익숙한 한 사람이 **가족 공용 계정**을 만들고 장보기·재고·식단·클라우드 동기화를 관리한다.
- 엄마·아빠는 Family Flow에 가입할 필요가 없다. 같은 기기에서 공용 로그인만 쓰면 된다.
- 화면의 “가족”은 **사람 이름·역할 메모**이지 각자 로그인 계정이 아니다.
- 초대 코드·멤버별 Auth는 **나중에 필요할 때만**. S5 기본 UX의 중심이 아니다.
- 부모 사이트 비밀번호를 앱에 저장·공유하는 기능은 기본 범위가 아니다.

온보딩(배포됨): 미로그인 시 로그인/가입 우선, 가입 시 집 이름 → 가구 생성. [DECISIONS.md](DECISIONS.md) §2.

## 계층

1. **규칙 엔진 (필수, 구현됨):** 재고·식단 등으로 필요한 일을 먼저 제안. AI 없이도 동작.
2. **AI 대화 엔진 (선택, 구현됨):** 자연어 → ActionProposal 후보.
3. **AI Provider (구현됨):** **로컬 패턴 → Ollama → Groq(Edge 무료) → 규칙.**  
   NVIDIA NIM은 과거 검토·주석 수준이며 **현재 운영 경로가 아니다.**
4. **승인 파이프라인 (구현됨):** proposal → 검증 → 미리보기 → 사용자 승인 → 저장.
5. **민감 데이터:** 건강 등 개인 민감 정보는 외부 AI에 기본 전송 금지.
6. **오프라인:** 규칙·장보기·재고는 동작. cloud-primary 오프라인은 읽기 전용. 대화는 연결 없음 폴백.

## 구현 단계 요약 (코드 기준)

체크리스트 최신본은 PROJECT_GUIDE. 여기서는 단계 이름만:

- S0 방향 문서화
- S1 제안 엔진 + 홈 (규칙) — 구현
- S2 ActionProposal 승인 UX — 구현
- S3 Ollama provider — 구현
- S4 대화 → proposal — 구현
- S5-A / A′ 공용 계정·초대 UI 숨김 — 구현
- S5-B 다기기 sync·가족 프로필 — 구현
- Auth-first 온보딩 — 구현·Pages 배포
- S5-C 오프라인 쓰기 큐·패턴 학습 — **미구현·미승인**
- GitHub Pages 배포 — **구현됨** (S5-C와 묶지 않음)

과거 캔버스 「A형 방향 재검토」원본은 현재 Agent/저장소에서 **확인 불가**.
